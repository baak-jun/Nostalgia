# 사진 정리 앱 규칙서 (v0.1)

## 1) 목적
- 갤러리 내 불필요한 사진(오촬영, 중복 느낌, 오래된 스크린샷 등)을 빠르게 분류한다.
- 즉시 삭제 대신 `검토함`에 모아두고, 나중에 안전하게 일괄 삭제한다.
- 사진에 태그를 붙여 텍스트 검색으로 원하는 이미지를 다시 찾을 수 있게 한다.

## 2) 핵심 제품 원칙
- 삭제는 항상 `2단계`: 분류 -> 검토 -> 최종 삭제.
- 사용자 신뢰 우선: 원본 자동 삭제 금지, 삭제 전 개수/용량/대상 명확히 표시.
- 빠른 행동 우선: 스와이프/멀티선택으로 최소 탭으로 분류 가능해야 한다.
- 검색 가능성 우선: 태그는 언제든 추가/수정 가능해야 한다.

## 3) MVP 범위 (반드시 먼저 구현)
- 갤러리 사진 목록 불러오기.
- 분류 액션:
  - 게임 reigns처럼 좌 우로 넘기는 것으로 함. 왼쪽으로 넘기면 검토함으로 이동, 오른쪽으로 넘기면 보관(보관만 할지, 태그를 달 수 있도록 할지 설정에서 변경 가능)
    넘기지 않고 사진 아래를 누르면 바로 태그 달고 보관되도록 함.
  - `검토함으로 이동`(삭제 후보)
  - `태그 추가`
- 태그 기반 검색:
  - 단일 태그 검색
  - 다중 태그 AND 검색
- 검토함 화면:
  - 후보 목록 확인
  - 선택 삭제(시스템 휴지통/삭제 API 호출)
  - 선택 복원
- 통계:
  - 검토함 개수
  - 예상 절약 용량

## 4) 제외 범위 (v1 이후)
- 클라우드 동기화
- AI 자동 분류(블러 감지, 사람/문서 인식)
- 계정/로그인
- 앨범 자동 규칙 추천

## 5) 데이터 규칙
## 5.1 엔티티
- `PhotoItem`
  - `id`(기기 고유 식별자)
  - `uri` 또는 접근 경로
  - `createdAt`
  - `width`, `height`, `sizeBytes`
  - `isScreenshot`(메타데이터/경로 기반 추정)
- `Tag`
  - `id`
  - `name`(소문자 정규화 저장)
  - `createdAt`
- `PhotoTag`(N:N)
  - `photoId`
  - `tagId`
- `ReviewCandidate`
  - `photoId`
  - `reason`(user_selected/screenshot/duplicate_hint 등)
  - `markedAt`

## 5.2 태그 정책
- 태그는 공백 trim 후 저장.
- 대소문자 구분 없이 중복 금지(`Travel` = `travel`).
- 특수문자 허용, 길이 1~30자.
- 권장 태그 최대 20개/사진(하드 제한 50개).

## 5.3 삭제 정책
- 앱 내부에서 먼저 `검토함` 상태만 저장한다(즉시 파일 삭제 금지).
- 최종 삭제는 사용자 명시 동작일 때만 실행.
- 삭제 직전 확인 다이얼로그에 다음 표시:
  - 삭제 개수
  - 총 용량
  - 복구 가능 여부(OS 정책)

## 6) UX 규칙
- 홈 탭: `전체`, `스크린샷`, `검토함`, `태그`.
- 사진 카드 기본 액션:
  - 좌스와이프: 검토함
  - 우스와이프: 보관
  - 롱프레스: 멀티선택
- 태그 입력 UX:
  - 최근 태그 자동완성
  - 쉼표/엔터로 연속 입력
- 빈 상태 문구 제공:
  - 검토함 비었을 때
  - 검색 결과 없을 때

## 7) 성능 규칙
- 썸네일 우선 로딩, 원본은 상세 화면에서만 로딩.
- 목록 첫 진입 2초 이내 표시(체감 기준).
- 스크롤 중 프레임 드랍 최소화(지연 로딩 + 캐시).
- DB 쿼리는 인덱스 기반:
  - `Tag.name`
  - `PhotoTag.photoId`, `PhotoTag.tagId`
  - `ReviewCandidate.markedAt`

## 8) 기술 규칙 (Flutter)
- 폴더 구조는 feature-first:
  - `lib/features/gallery`
  - `lib/features/review_bin`
  - `lib/features/tags`
  - `lib/core`
- 상태관리는 한 가지로 통일(권장: Riverpod).
- 로컬 저장소는 SQL 계열 우선(권장: `sqflite` 또는 `drift`).
- 갤러리 접근은 플랫폼 권한 라이브러리 사용(예: `photo_manager`).
- 모든 삭제 관련 함수는 `Dry-run` 계산 함수와 실제 실행 함수를 분리.

## 9) 품질 규칙
- 테스트 최소 기준:
  - 태그 정규화/중복 방지 단위 테스트
  - AND 검색 쿼리 테스트
  - 검토함 추가/복원 상태 테스트
- 크래시 방지:
  - 권한 거부 시 가이드 화면 제공
  - 파일 접근 실패 시 해당 항목만 스킵하고 전체 동작 유지

## 10) 릴리즈 기준 (MVP)
- 실제 기기에서 1,000장 이상 로딩 가능.
- 태그 추가/검색/검토함 이동/복원/삭제 플로우 동작.
- 치명적 크래시 0건.
- 권한 요청/거부/재요청 플로우 정상 동작.

## 11) 우선 구현 순서
1. 갤러리 읽기 + 썸네일 목록
2. 검토함 상태 저장(로컬 DB)
3. 태그 CRUD + 태그 검색
4. 검토함 일괄 삭제/복원
5. 통계(절약 용량, 개수)

## 12) 결정 보류 항목
- iOS/Android 삭제 API 차이 처리 상세 정책
- 중복 사진 판정 기준(hash/perceptual hash)
- 태그 추천 로직(최근/빈도/AI)
